# 01｜UI・キャラクター・演出
レーンの可読性を主役にし、背景とちゃちゃまるで豪華さを出す。無関係な管理画面風にしない。

## 1. 美術基準
赤柴、白い口元・頬・胸・足先、三角の立ち耳、巻き尾、緑の唐草スカーフ、ひまわり飾り。
暖かい金色の夕空、和風の家並み、山、ひまわり、提灯。サビは夕暮れのお祭りへ。
チープな絵文字犬、標準アイコンだけ、四角い仮図形だけで終わらない。
元画像の敵・ジャンプボタン・体力ハート・横移動を引き継がない。

背景と犬は別。背景画像に焼き込まれた犬を丸ごと上下移動するだけは不合格。
素材生成ツールが使える場合は一貫した基準絵から作る。追加有料APIを勝手に契約しない。
使えなければ、独自のSVG/ベクターパーツ・陰影・テクスチャで一体感を作る。
素材生成の不在を理由に、キャラと視覚検証そのものを省略しない。

## 2. レイアウト座標
safe-areaを差し引いた表示領域をSw×Shとする。バーによるresizeを監視。
横画面：論理H=720、W=clamp(960,720*Sw/Sh,2000)。
scale=min(Sw/W,Sh/720)。中央配置。初期基準はW=1280,H=720。
縦画面は後述。これらはCSSピクセルではなく論理座標。

| 領域 | 基準の座標とサイズ |
|---|---|
| HUD | x24,y12,w=W-48,h72 |
| レーン外枠 | x24,y100,w=W-48,h168 |
| 判定円 | x=clamp(132,W*0.13,220), y184, radius44 |
| ノーツ | y184, 通常radius27、大radius36 |
| レーン右端 | W-42 |
| 曲進行 | x28,y278,w=W-56,h5 |
| キャラ/背景ステージ | x24,y292,w=W-48,h238 |
| タッチパッド | x24,y542,w=W-48,h162、4分割、gap12 |
| ちゃちゃまる | 中心x=W*0.38、足元y522、高さ210 |
| コンボ節目の文字 | x=W*0.68,y348、最大w=W*0.40 |
| 通常コンボ数 | HUD内、表示枠固定、桁増えで位置を動かさない |

MIDIモード：パッドを折り畳み、stageをy292〜688へ拡張。犬の高さ300。
右下に「スネア=ドン / フロア=カッ」と試打インジケーター。pauseは常時見える。
レーン判定円とノーツは演出時にも座標・スケールを変えない。
左右の装飾太鼓は置いてよいが、可視ノーツ数を不必要に減らさない。

縦画面：論理720×1280。HUD y16〜116、レーンy150〜320、
stage y350〜930、4打面y980〜1235。各pad幅158、gap12。横向き案内はdismiss可能。
重要ボタンの実表示高さ44 CSS px以上。設定文字は最低16 CSS pxを目安にclamp。
play中は画面のスクロール・ダブルタップズームを打面領域に限定して抑える。
設定画面の通常スクロールは殺さない。

## 3. 色・形
独自テーマの設計値：
don #F35A43、ka #2CBBD5、gold #FFD86B、ink #1E1726、cream #FFF2CE、green #467843。
ノーツは明るい色面＋cream縁＋ink輪郭、中央に独自の小さな犬耳/表情。
本家の顔パーツやテクスチャは抽出しない。don/kaを色以外にも文字で区別。
レーン背景は暗色不透明寄り。背景の明るさが変わっても読める。
巨大なグラデーションカードやglassmorphismだけの画面は避ける。

## 4. キャラの構造
最低限の独立部位：胴、頭、耳左右、前脚左右、後脚左右、巻き尾、スカーフ。
太鼓演奏ポーズでは前脚にバチを持つ。最低8状態：
idle / don / ka / happy / comboJump / chorusDance / miss / resultWin。
ボーン又は手動パーツリグを用いてよい。必須の有料アニメーションソフトは作らない。

idle：拍に合わせ上下2〜4px、尻尾±8°、瞬き3〜5秒間隔。
don：前脚を40msで下ろし、90msで戻す。胴を短く3%圧縮。連打で処理を溜めない。
ka：反対の前脚、尻尾の小さな振り。donと同じ動きを色だけ変えない。
comboJump：350ms、最大高さ24px、着地時に独立した足と尾が遅れて戻る。
chorusDance：2拍ループ。足踏み＋前脚＋頭＋スカーフが連動する。
miss：120msだけ「おっと」。長い悲しみ・画面停止・叱責音は禁止。
resultWin：全身ポーズ→紙吹雪→小さなループ。全良は王冠又はひまわり輪。

beatMarkers間を補間した拍位相で踊る。描画フレームを積み重ねて拍を作らない。
高速連打では最後の入力を優先し、1打ずつのアニメーションを長いqueueにしない。

## 5. 演出イベント表（仕様値）
| trigger | 視覚 | 時間 | 音 |
|---|---|---:|---|
| correct good | 判定円で金色ring、ノートから10粒、文字「良」 | 140〜220ms | 入力の打音のみ |
| correct ok | 小ring4粒、文字「可」 | 140ms | 同じ入力打音 |
| miss | 小さな灰色破片、文字「不可」 | 160ms | 原則なし |
| combo10 | 数字1.00→1.16→1.00、尾リアクション | 220ms | 小さな鈴 |
| combo50 | 犬jump、花びら18粒、短い帯 | 600ms | 短いchime |
| combo100+ | 犬jump＋金色印、仲間が最大4匹に増える | 900ms | 3音fanfare |
| chorus start | 背景blend、提灯点灯、花火2発 | 800ms transition | 短い上昇音、曲を覆わない |
| chorus end | 夕景へ戻る | 1000ms | なし |
| full combo result | ひまわりの輪、紙吹雪、専用文字とpose | 2400ms | オリジナルfanfare |
| all great result | 金色の追加紋、星、冠 | 2800ms | 専用の短い終止形 |

10/50/100が同時に成立したら最大の1つだけ。100以後は100刻みで大演出。
毎打の打音・ringは省略しない。大型演出は8件も遅延queueせず最新・最高優先だけ。
resultの大演出は曲末まで待つ。最後の音符を叩いた瞬間に曲を切らない。
サビ演出は譜面sectionの[s,e)。コンボと独立。失敗してもサビの音楽的変化は維持。
画面全体の点滅・ヒットストップ・レーン揺れは禁止。強いフラッシュを成功の必須要素にしない。

## 6. 音
BGM、hit、effect、UIに別GainNode。hitはMIDIモードだけ既定0。
don：低い胴鳴りと短いアタック、ka：高い木質クリック。両方オリジナル素材。
エフェクト音で毎打の打音を重ねて鳴らさない。1入力にhit音は最大1回。
短いイベント音を主役にし、人声の長い読み上げやspeechSynthesisを連打しない。
テクスチャ、効果音、音源に公開許可情報を `assets/manifest.json` で記録する。

## 7. 性能予算（目標値であって未測定の保証ではない）
render解像度倍率はmin(devicePixelRatio,2)。発熱/負荷で1.5へ下げられる。
ノート・粒子はpool化。曲の全イベントを毎frameでDOMとして作り直さない。
粒子上限standard160、reduced40、off0。ノーツ・文字・入力はoffでも残す。
通常プレイの移動窓5秒でframe間隔p95>25msが3回続いたら負荷軽減を提案/適用。
演奏中にZIP展開・音源解析・DB大規模移行・アップデート適用をしない。
デスクトップの60fps確認を、iPhone実機の60fps確認と書かない。

## 8. 目視で保存する画像
Home、Library、Playing通常、Playingサビ＋100combo、MIDI表示、Portrait、Result全良、Studio。
開発用 `#/showcase` で本番のコンポーネントに固定seed/fixture状態を注入できるようにする。
showcaseはスクリーンショット用。記録更新禁止、実際の演奏試験の代替にはしない。
スクリーンショットを開いて、切れ・重なり・文字・参照との方向性を確認して修正する。
