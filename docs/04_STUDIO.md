# 04｜Mac Studio：解析・編集・書き出し
ユーザーが毎回CLIを使う設計にしない。CLIは自動試験・Codex用に残す。

## 1. 起動とデータ
rootで `npm run studio` → loopbackサーバー起動 → ローカルブラウザを開く。
この操作をまとめた `Start Studio.command` を生成し、2回目以後はダブルクリックで使えるようにする。
初回のmacOS権限/依存導入は環境依存。chmodやGatekeeper回避を勝手に広範囲変更しない。
データ保存先：`~/Music/ChachamaruPacks/`を既定とし、ユーザー指定で変更可能。
リポジトリのpublicやsrc内へprivate音源を置かない。iCloudへはユーザーが保存/移動する。
原曲は上書きせずcopyで処理。Logicプロジェクトを自動探索・改変しない。
公開版Studioに解析ボタンがあっても、Macで動作するAPIがあるように偽装しない。
公開ページでは「Mac版Studioを起動」と説明。ブラウザ単独のZIP編集は可能にしてよい。

## 2. 画面
デスクトップ基準1440×900、左220pxにプロジェクト/曲情報、中央に波形と譜面、
右280pxに選択ノート/難易度/解析警告、下80pxに再生と書き出し。
上部：音源を追加、保存、かんたん/ふつう/むずかしい切替、iPhone用ZIP書き出し。
中央timeline：波形、beat/downbeat、2色ノート、chorus区間、playhead。
ノート追加はD=don、K=ka、Delete=削除。input欄入力中はshortcutを発火しない。
Macでの試遊は同一プレイヤー/同一判定コードを使う。別の仮プレビューでごまかさない。

## 3. 処理パイプライン
STAGED → TRANSCODING → ANALYZING → GENERATING → REVIEW_READY → EXPORTING → EXPORTED。
error/cancelから安全に戻せる。重い処理は1job、子processの停止とtemp cleanupを実装。

1. ffprobeで音声トラック、duration、ch、sampleRateを確認。
2. 最終配布音源を作る。既定AAC-LC/m4a、44.1kHz、stereo、192kbps。
   強制的な冒頭無音除去・テンポ変更・音量正規化は既定off。原音は変更しない。
   元がmonoならmonoのまま可。WAV診断はPCM16で保存。
3. **作成済みの最終配布音源を**再デコードして解析用mono22.05kHz PCMへ。
4. SHA-256を計算し、librosaでonset strength、beat候補、RMS等を計算。
5. beatTimesMs/区間候補/波形ピーク/診断情報を保存。
   分離の準備があるMacでは、ここで曲を歌・ドラム・ベース・ほかの楽器に分ける（Demucs htdemucs、`stems.py`）。
   分けた音から特徴を作って `features.json` に入れ、分けた音そのものは消す（「歌とドラムを聞き分けています」）。
6. 同じbeat列から3難易度の下書きを決定論的に生成。
7. ユーザーに「自動下書き・要試聴」を表示し、編集可能にする。
8. validationしてZIPへ。音源は再エンコードし直さない。

Python依存はpyproject＋lockへ固定。librosaの実際のreturn型と採用版を確認（S10）。
librosa+FFmpegが通常経路。Logicや巨大な機械学習モデルの導入を必須にしない。
音源分離は任意（ユーザーの判断で導入、2026-09-30）。
- 準備：`scripts/setup-stems.sh`。Demucs・PyTorch（`studio/stems.lock`）を譜面工房とは別のPython環境 `_private/stems-venv` に入れる。
- モデル：htdemucs（約80MB）を Meta の配布サーバー（dl.fbaipublicfiles.com、ハッシュ確認つき）から `_private/models` に取得する。
- 準備がないMac、GitHub Actionsでは曲全体の音だけで動く（テストは分離なしでも通る）。

## 4. 拍解析の初期アルゴリズム
analysis sr=22050、hop_length=256を初期値。
onset envelope→beat tracker。beat frameをtimeMsへ変換。
global BPMはUIの参考値。runtimeはbeat時刻そのものを保存・使用。
倍/半分BPM候補を表示し、1/2・2倍ボタンでユーザーが選べる。
拍候補が少ない/間隔の変動が大きい/無音が長い場合は警告を表示。
信頼度はheuristicラベル(low/medium/high)。科学的な正解確率として%表示しない。
失敗しても任意BPM、最初の拍ms、4拍/小節による手動gridを作れる。
テンポ固定でない曲は手動区間補正または直接beat移動を許す。固定BPMで押し切らない。

サビは「盛り上がり候補」としてenergy上位のまとまった8〜32秒区間を最大3つ提案。
歌詞内容・意味的サビを理解できたと称さない。候補はconfirmed=false。
手動で開始/終了を変更し、確認ボタンでtrueにできる。
demo曲は作曲時に明示したsectionを使い、確実に演出を見せる。

## 5. 自動譜面生成の規則（v7、2026-09-30）
曲の目立つ音を、曲自身の拍の格子で追いかける。静かな所は少なめ、にぎやかな所は多めになる（最初の版 v2 の良さ）。
そのうえで、1小節のリズムをまとめて選び、手作りの譜面のように読みやすく整える（`studio/chacha_studio/patterns.py`）。原曲の採譜ではなく、編集前提の下書き。

- 拍の格子（`steady.py`）：クリックに合わせた録音のように、最初から最後まで同じテンポの曲は、一定間隔の格子に引き直す。
  - 拍の検出は、音の詰まった曲では途中で少し遅れたり半拍ずれたりする。そのままだと、曲の表拍が譜面の裏拍になり、小節の区切りも崩れる。
  - 格子が曲の16拍ごとの区間の85%以上で音に合い、元の拍より音によく乗るときだけ使う。曲の頭と終わりで合わない区間（自由なテンポのイントロなど）は元の拍のまま。テンポが途中で変わる曲は元の拍を使う。
- 目立つ音（音源分離があるとき、`stems.py`）：
  - 歌がいちばん重い。歌のない所では、ほかの楽器（リフ・ソロ）が主役で、ドラム（ハイハットを含む）が支える。
  - 早口の歌は立ち上がりが弱いので、近く2秒の中でいちばん強い音と比べた強さも半分数える。
  - 歌う所でどれだけ歌に寄せるかは、テンポで変える：140 BPMまでは歌に寄せる（ドラムを軽く、裏拍を重く）。200 BPMからは拍を基準にする（速い曲の裏拍は読みにくい）。その間はなめらかに変える。
  - 分離がないときは、曲全体の音の立ち上がり（歌・メロディ・ドラム）を使う。
- 1小節のリズムの選び方：
  - 価値＝音符の強さの合計−音符1つあたりのコスト（曲全体で同じ。これで密度が決まる）−読みにくさのコスト。
  - 読みにくさ：自分の拍にも前後の拍にも音符がない裏拍（ふつう・むずかしい）、16分（むずかしい）。どちらも速い曲ほど高い（160 BPMを基準に、テンポに比例）。
  - 前の小節、または2小節前（歌のフレーズと、それに答える次のフレーズ）と同じリズムは少し得をする。小節の形は、曲が変わる所で変わる。4小節のフレーズの最後の小節では、この得を半分にする（フィルや歌の区切りで変わってよい）。
  - 音符を置くのは、その小節とくり返しの組の過半数で、音が鳴っている位置だけ。
  - 音が鳴っている小節には、最低でもかんたん1・ふつう2・むずかしい3の音符を置く（歌のない間奏が空にならない）。
  - 16分を使わないとき（ふつう、速い曲のむずかしい）は、16分の位置の歌の音を、隣の8分・拍の位置の音として数える（人が簡単にするときと同じ）。
- 3つの難易度は1本のはしご：
  - ふつう：拍と8分から選ぶ。8分の連続は、8分が180ms以上なら5打、150ms以上なら4打、それより速ければ3打まで。
  - むずかしい：ふつうの各小節に音符を足す。16分は8分の位置から始まる組（「ドコ」「ドコドン」、3打まで）だけで、16分の間隔が90ms以上（166 BPMまで）のときだけ。それより速い曲は8分まで。
  - かんたん：ふつうの拍の頭から選ぶ。1・3拍目と、ふつうでカッの拍を少し選びやすくする（2色で遊べるように）。
  - 同じ音符はどの難易度でも同じ色。かんたんで覚えたリズムと色が、上の難易度でもそのまま使える。
- くり返す部分は同じ譜面（1番と2番のAメロ、各サビ）。くり返すうちに覚えて上達できる。
  - 見つけ方：曲の平均の小節との違い（和音の流れと、歌・メロディ・全体の音の出だし）で比べる。ある距離だけ前の8小節と、ほかの距離よりはっきり一致する部分とする（`generator._repeat_groups`）。
  - 結ぶ2つの小節そのものも似ていること（リズムの似方0.5以上、にぎやかさが半分以上）。部分の終わりの小節や、静かなアウトロを、違う部分と結ばない。
- 色：ふつうで決め、かんたんは引き継ぐ。むずかしいは、足した音符に色を付ける。
  - 1音ずつの傾き：スネアがバスドラムより強いほどカッ、明るい音ほどカッ。2・4拍目と裏拍はカッ寄り、3拍目はドン寄り、1拍目はいつもドン（分離があるときは、分けたドラムで判断する）。
  - 小節ごとに決める：くり返しの2回目以降は1回目と同じ色。前の小節（または2小節前）と同じリズムなら、その色を引き継ぎ、音がはっきり変わったとき（スネアが入るなど）だけ変える。
  - むずかしいで足した音符は、同じリズムの隣の小節でふつうが同じ位置に置いている音符の色に合わせる。16分の組は最初の音符の色。
  - カッの割合：曲全体で1つの基準値を調整し、ふつう・むずかしいで18%以上にする。上限はかんたん20%（弱いカッの拍を外して抑える）、ふつう30%、むずかしい32%。
- 大音符：サビの頭、2拍以上の休みのあと、くり返し部分の同じ場所（ふつうの4%以内）。どの難易度も、最後の音符は大音符。
- 連打：ドラムのフィル（2拍以上、ほぼ全部の16分でドラムが鳴る所）に置き、20秒に1本まで。分離があるときは、分けたドラムで探す。フィルが見つからない曲は、サビの前に置く。
- 拍の取り違えの補正（ドラムがあるとき）：
  - 速い曲を2/3のテンポで取ると、3連符に見える。1.5倍のテンポの方がドラムがよく繰り返すときは、1.5倍で取り直す。
  - バスドラとスネアが拍と拍の間にあるときは、拍を半拍ずらす。
  - 小節の頭は、スネアが2・4拍目に来る位置を重く見る。

制約（設計既定）：
| 難易度 | 目標密度 | 最小間隔 | ka上限 | 速い束の上限 |
|---|---:|---:|---:|---:|
| easy | 1.15打/秒 | 180ms | 20% | 拍の頭のみ |
| normal | 2.25打/秒 | 105ms | 30% | 8分の連続は5・4・3打（テンポによる） |
| hard | 3.3打/秒 | 75ms | 32% | 16分は8分から始まる組・3打まで、166 BPMまで |

- 最初のnoteは原則800ms以後、末尾は音源終了300ms前まで。rollはtapとの±90ms競合を作らない。乱数は使わず、同じ入力なら同じ譜面になる。
- 再生成は、既存の編集を上書きする前にUIで確認し、元の編集版をrevisionとして残す。
- 前に作った曲は、最初の再生成で解析データ（ドラム・メロディ・和音）を作り、拍と小節の頭も直す。生成器が v6 より前の曲は、次の再生成で1回だけ拍の格子を調べ直す。譜面工房の「譜面を作り直す」で、選んだ曲の3難易度をまとめて作り直せる。

品質の確かめ方：
- 同梱曲の手作り譜面との一致度を測るベンチマーク。音符の位置（±30ms）と色を、手作り譜面と比べる。拍の頭の音符は当たりやすいので、裏拍の音符だけの一致も見る。
- このMacの曲で、採点表を作って比べる。
  - 音との一致：分けた音の強い所に乗る音符の割合、歌の目立つ音を拾う割合。
  - 読みやすさ：前後の拍にも音符がない裏拍、速い連続の長さ、速い連続の中の色の切り替え、最短間隔。
  - まとまり：1・2・4小節前と同じリズムの小節の割合、8小節の中のリズムの種類、同じリズムで色だけ変わる小節の割合。
  - 単調さ：4分音符だけの小節の割合、同じ小節がいちばん長く続く数。
  - 抜け：音が鳴っているのに音符が少ない小節の割合と連続。
  - その他：難易度どうしの包含と色の一致、連打と大音符の数。
- 合成曲のテスト（`tests/python/test_song_draft.py`、`test_patterns.py`、`test_stems.py`）。

比較用の作り方（分離の有無は `features` の `stems` で切り替わる）：
- `style='v5'`：目立つ音を1つずつ選ぶはしご（`ladder.py`）。速い曲では無秩序で難しいとユーザーが判断した版。
- `style='v4'`：難易度ごとに別々に選ぶ版。
- `style='v2'`：最初の版。
- `style='drums'`：v3。ドラムだけで単調とユーザーが判断した版。

## 6. 編集の必須操作
音源再生/停止/小節ループ、波形zoom/水平pan、playhead移動、AUTO試聴。
ノート追加/削除/drag移動/色変更/大音符切替、複数選択、undo/redo最低100操作。
snap=off/1/4/1/8/1/16、左右矢印±5ms、Alt併用±1ms。
全譜面offset±1/5/10ms、テンポ/先頭拍の修正、サビ開始/終了/確認。
選択範囲のdon↔ka変更、密度警告、曲末超過・roll重なりの可視化。
Studioのseek/loop中はpractice扱い。プレイヤーの最高記録に混ぜない。
速度変更はLATER。まず通常速度の同期を確実にする。
編集後500ms debounceでプロジェクト保存。書出時も保存完了を待つ。

## 7. ローカルAPI契約
同一originのFastAPI＋静的Studio画面。127.0.0.1:8787を初期候補、使用済みなら別portを表示。
GET /api/health → {ok,apiVersion,ffmpeg,analysisAvailable}
GET /api/session → {csrfToken}（same-origin/loopbackのみ）
POST /api/jobs（multipart audio + title + artist）→202 {jobId}
GET /api/jobs/:id → {status,progress,message,error?,projectId?}
DELETE /api/jobs/:id → cancel
GET /api/projects/:id → project（編集用データ。任意filesystem pathは返さない）
PUT /api/projects/:id → validateして保存。revisionによる楽観ロック、不一致409
POST /api/projects/:id/generate → {difficulty,options}、非同期job
POST /api/projects/:id/export → validate→{exportId}
GET /api/exports/:id → authenticated ZIP download
GET /api/projects/:id/audio → private audio。same-origin/token検証。
mediaタグへtokenをqueryで公開せず、認証fetch→Blob URLを用いる。

ホスト127.0.0.1/localhostのみ、外部Origin拒否、CORS wildcard禁止。
起動ごとの乱数token、変更操作にheader token必要。session tokenを公開HTMLへ固定しない。
shell=Falseのsubprocess引数配列、外部URL入力禁止、projectId→管理下dirへ限定。
APIから任意ファイルread/write、任意コマンド実行、外部URL fetchを提供しない。
uploadサイズとjob数を制限。privateデータをGitHub Actionsへ送らない。

## 8. Logic
Smart Tempo等の補助は任意。ユーザーが手動で用意した音源/ステムを使ってよい。
ただし提供されていないComputer Useを仮定せず、通常パイプラインの完成を先に進める。
Logicが開けないことを初版全体のblockerにしない。
最初のgoalで追加の有料音源・プラグイン購入はしない。
