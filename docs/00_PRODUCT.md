# 00｜製品仕様
規範語：MUSTは初版の完成に必要。LATERは今回のgoalから除外。

## 0. このゲームの目的
「好きな曲に合わせて2色の音符を叩き、ちゃちゃまると一緒に祭りが盛り上がる」個人用ゲーム。
ユーザーにプログラミング、譜面JSON編集、毎回のコマンド入力を要求しない。
Macで曲を作る時だけStudioを起動。iPhoneで遊ぶ時はMac不要。

タイトル既定値：**ちゃちゃまる太鼓の達人**（ユーザー指定の作業名）。
文字列は `brand.ts` 一箇所にまとめ、公開時の名称整理を可能にする。勝手に改題しない。
公開前チェックに独自公開名の検討を残す。公式ロゴ・公式キャラクター・公式音声は使わない。

## 1. MUST機能一覧
P0-01 起動・曲選択・難易度・演奏・結果・再試行の全導線。
P0-02 2色一本レーン。右から左へ流れ、左の判定位置で叩く。
P0-03 通常ドン／カッ、大音符（1打完了アシスト）、黄色連打。
P0-04 iPhone向け4打面マルチタッチとMacキーボード操作。
P0-05 MIDIポート選択、MIDI Learn、入力モニター、接続切断対応。
P0-06 良／可／不可、コンボ、得点、クリアゲージ、フルコンボ、全良。
P0-07 ちゃちゃまるの独立した身体アニメーション、コンボ・サビ・終了演出。
P0-08 音楽と打音の個別音量、タッチ/MIDI音声モード、遅延設定。
P0-09 ZIP曲パックの取込・検証・一覧・削除・再読み込み時の復元。
P0-10 設定・記録のエクスポートと復元。
P0-11 Studio：音源投入、拍解析、3難易度の下書き、自動保存、編集、ZIP出力。
P0-12 オリジナル64秒デモ曲、3難易度。ユーザー音源なしでも全画面を試せる。
P0-13 診断・互換性表示・テスト・GitHub Pagesビルド・README。

SHOULD：Service Workerによるオフライン起動、Wake Lock、全画面化。
未対応時にゲームが壊れないことはMUST。PWA追加でMIDI機能が引き継がれるとは説明しない。
LATER：風船、分岐、対戦、ランキング、ガチャ、キック、5レーン、歌詞同期、

## 2. 画面と遷移
ルートはhash方式。GitHub Pagesのサーバー側rewriteを要求しない。

| 画面 | route | 内容・主要操作 |
|---|---|---|
| Home | #/ | ロゴ、ちゃちゃまる、はじめる、曲追加、設定、接続診断 |
| Library | #/songs | デモ＋私用曲、検索、難易度、入力方式、選択曲の開始 |
| Import | #/import | ZIP選択、検証進捗、エラー、成功後に曲一覧へ |
| Play | #/play/:songId/:chartId | 読込、開始タップ、カウントイン、演奏、pause |
| Result | #/result/:runId | 結果、リトライ、曲一覧、詳細タイミング |
| Settings | #/settings | 音量、演出、補正、保存、バックアップ |
| Diagnostics | #/diagnostics | API、入力、音声、ストレージ、ログ出力 |
| Studio | #/studio | デスクトップ編集。解析APIはMacローカルのみ |

画面移動で一曲分のAudioBuffer以外を溜めない。戻る・ブラウザ再読み込みで古い演奏が残らない。
存在しないsongId/chartId/runIdは「データがありません」とし曲一覧へ戻す。
読込失敗はリトライと戻るを出す。無限spinnerは禁止。

## 3. ユーザーフロー
### 初回のスマホ
Home→「はじめる」→デモ曲・かんたん選択→開始タップ→音声をunlock→2秒準備→演奏→結果。
起動直後の勝手な音声再生はしない。端末回転は促すだけで強制条件にしない。

### 初回のTD-17
設定→「電子ドラム」→MIDI接続→ポート選択→スネアを叩く→don登録→フロアタムを叩く→ka登録→保存。
同じnote/channelを両方へ登録しようとしたら説明してやり直す。
チャンネルは画面で1〜16、内部では0〜15。noteとchannelの組で保存。
「MIDIが見つからない」でもタッチ・キーボードで遊べる。

### 曲追加
MacでStudioを起動→音源をdrop→解析→譜面試聴・必要時修正→ZIP保存→自分のファイルへ転送。
iPhoneのゲームで「曲を追加」→ファイル選択→取込→選曲。
ZIPをFilesへダウンロードしただけで自動登録される設計にしない。

## 4. 演奏の状態機械
BOOT → LIBRARY → LOADING → READY → COUNT_IN → PLAYING → FINISHING → RESULT。
PLAYING → PAUSED → COUNT_IN → PLAYING。
LOADING失敗→LOAD_ERROR、MIDI切断/非表示/音声停止→PAUSED。
PAUSEDからRETRYは新runIdで頭から。LIBRARYへ戻る時は音源とイベントを破棄。
COUNT_IN中の入力はパッド試打だけ可能。得点・ミスは発生させない。
音源終了と判定の最終確定の両方が揃ってFINISHINGへ。
途中でゲージが0になっても強制終了しない。

## 5. 入力ルール
4打面は左から ka-left / don-left / don-right / ka-right。
F/J=don、D/K=ka、Escape=pause、Enter=選択画面の開始/結果のretry。
MIDIの左右の手は判別しない。スネアの1打＝don、フロアタムの1打＝ka。
入力方式はtouch / midi / keyboard。途中切替はpauseで行いmixed記録として保存。

大音符：見た目1.35倍、得点重み2。正しい1打で良/可。両手同時は要求しない。
追加の2打目に点数を上乗せしない。ヘルプに「大音符アシストON（初版固定）」を出す。
黄色連打：[startMs,endMs)内のdon/kaを1打ずつ加算。長押し自動連打はしない。
連打0でもコンボは切らず、クリア失敗にしない。風船は実装しない。

## 6. 記録
記録キー：songId、chartId、audio SHA、chart SHA、ruleset、inputMode、practice/autoplay。
最高点、最大コンボ、良可不可、クリア/FC/全良、日時、設定プロフィールを保存。
AUTOと練習とmixedは通常最高点を更新しない。入力モード別に記録。
譜面変更でSHAが変わったら旧記録を新譜面の実績と混ぜない。履歴として残す。
結果でEARLY/LATE中央値を表示してよいが、物理遅延の測定結果とは呼ばない。

## 7. 既定設定
BGM=0.75、タッチ打音=0.65、演出音=0.40、MIDI時Web打音=0。
音量は0〜1のslider。Bluetoothプロファイルでも曲だけ別経路へ出し分ける機能は作らない。
演出=standard、画面揺れ=off、強い点滅=off、背景の祭り変化=on。
判定=normal(45/90ms)、譜面速度=1.8秒先が右端、FAST/LATE表示=on。
ミラーはLATER。小節線・ドンカッ文字はon、設定で文字だけoff可。
